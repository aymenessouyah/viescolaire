Le principe : découper, puis résumer

On part d’une table de collaborateurs — un nom, un département, un salaire en dinars — et on veut le total des salaires par département.

1. Les groupes

On prend les valeurs distinctes de la colonne : Finance, Informatique, RH, Achats, Ventes, Marketing. Chaque valeur donne un groupe.

2. Le résumé

Dans chaque groupe, on applique un calcul : la somme des salaires. Une ligne par groupe, pas une ligne par personne.

SELECT departement, SUM(salaire) AS total
FROM collaborateurs
GROUP BY departement;

La syntaxe de GROUP BY

Toujours quatre morceaux : la colonne de regroupement, la fonction d’agrégation, la table, puis le GROUP BY.

SELECT   colonne_de_regroupement,
         fonction_agregation(colonne)
FROM     table
GROUP BY colonne_de_regroupement;

À retenir

GROUP BY ne sert jamais seul : il s’accompagne toujours de SUM, COUNT, AVG, MIN ou MAX.

La colonne du GROUP BY doit figurer dans le SELECT.

Deuxième exemple

Sur la table des absences : GROUP BY type_absence avec SUM(duree_absence) donne le total des heures par type (congé, retard, maladie, maternité…).

En remplaçant SUM par MAX, on obtient la plus longue absence de chaque type.

HAVING : filtrer les groupes

WHERE filtre les lignes avant le regroupement ; HAVING filtre les groupes après. C’est toute la différence.

ClauseCe qu’elle filtreQuandExemple
WHEREles lignesavant le regroupementWHERE salaire > 2000
HAVINGles groupesaprès le regroupementHAVING SUM(salaire) > 5000
SELECT   departement, SUM(salaire) AS total
FROM     collaborateurs
GROUP BY departement
HAVING   SUM(salaire) > 5000;

Seuls les départements dont le total dépasse 5 000 dinars apparaissent.

L’ordre logique d’exécution

Le serveur ne lit pas la requête de haut en bas : il exécute dans cet ordre. C’est ce qui explique où chaque filtre a le droit de se placer.

FROM ➜ WHERE ➜ GROUP BY ➜ HAVING ➜ SELECT ➜ ORDER BY

Conséquence 1

HAVING ne peut pas être écrit avant GROUP BY : au moment où WHERE s’exécute, les groupes n’existent pas encore.

Conséquence 2

Un alias défini dans le SELECT n’est pas encore connu du WHERE : on ne peut pas l’y utiliser.

L’erreur à éviter

La faute la plus fréquente en devoir : mettre dans le SELECT une colonne qui n’est ni groupée, ni agrégée.

SELECT departement, nom, SUM(salaire)
FROM collaborateurs
GROUP BY departement;

Ici nom n’est ni groupé, ni agrégé : la requête est fausse.

Règle d’or

Toute colonne non agrégée du SELECT doit figurer dans le GROUP BY.

Récapitulatif

GROUP BY découpe les lignes en groupes.

L’agrégat résume chaque groupe.

HAVING filtre les groupes ; WHERE filtre les lignes, avant.
